### 踩坑

| 坑 | 现象 | 真因 |
| --- | --- | --- |
| 宝塔「域名」框三条校验 | `IP:端口` 报端口不合法、纯数字报格式错误、同 IP 报已存在 | 该框只做站点标识，需填占位子域名再去配置文件补 `server_name` |

| 登录 401 排查绕远路 | 健康检查正常、哈希看着也正常 | 项目里那个管理员账号的哈希与本项目验证函数不配套；正解是删号重建，不是查 MySQL 密码 |

| **push 反复失败** | `remote: fatal: did not receive expected object 9d16f105…` + `remote unpack failed: index-pack failed` | 仓库是从课程项目**浅克隆**来的，`.git/shallow` 让根提交 `d68cf0b` 的 parent 在本地不存在，GitHub 拒绝接收这种历史。修法：`git fetch --unshallow upstream main` 补全后正常推送 |
| `.env` 位置误判 | `docker exec ... cat /app/.env` 报不存在，一度以为没配 | `env_file: .env` 相对 compose 文件解析，生效路径是仓库根的 `.env`，容器内本就不该有 |

### 下次注意

1. **断言"代码缺失/镜像过期"之前，先在本地仓库 grep 找真实实现。** 一个 `ImportError` 不等于功能没写，更可能是自己 import 错了模块。这次因此白跑一次镜像构建，属于纯浪费。
2. **新增 import 前先查 `requirements.txt`。** 我往 `security.py` 加了 `passlib` 而项目只装了 `bcrypt`，若不是及时发现会直接让容器起不来。
3. **前端 `.catch(() => {})` 是排查黑洞。** 静默吞掉的 422 让一个改数字就能修的问题找了十几分钟；本地联调阶段至少临时打印一次错误。
4. **分页参数以后端 Query 校验上限为准**，本项目统一 `le=50`。要一次拉全量就翻页，别赌大数。
5. **静态站点发布一律整包压缩上传**，并在解压后核对 `assets/` 里的 hash 与 `index.html` 引用一致；验收前 Ctrl+F5。
6. **线上初始化管理员不必重建镜像**，`docker exec` 直接调容器内模块即可；把命令固化进部署手册第 10 节。
7. **改 `.dockerignore` 要基于原文件增量调整**，不要整篇重写。这次把原作者的注释和 `.env.*`、`!.env.example` 等规则一并抹掉了。
8. ~~演示环境仍是 HTTP + IP，未走 HTTPS/备案；对外演示前如需证书，按手册第 9 节做 DNS 验证签发的免费证书。~~
   **本条已被 S11 实测推翻**：未备案域名连 8080 都会被阿里云拦成 403，走域名必须先备案。见下方 S11 踩坑表。
9. **push 报 `did not receive expected object <SHA>`，第一步 `cat .git/shallow`，不要猜网络。**
   本次我连续误判六次（大陆网络不稳 → thin pack → 子模块 gitlink → 本地仓库损坏 → 旧仓库服务端状态 →
   代理与 TLS 后端），还让用户白删重建了一次仓库。
   其实决定性证据很早就在手上：**换一个全新的空仓库仍然报同一个 SHA**，就足以排除所有远端与网络因素，
   只剩"我们发出去的包里有一个拿不出来的对象引用"这一种解释——那正是浅克隆的 parent。
   通用教训：同一个错误在"应该无关"的两个对象上字节级复现，说明原因在自身，不在环境。

## 2026-09-20 · S11 小程序端品牌统一 + 全仓去上游痕迹

网页端早已改名，小程序端和后端仍满是「鱼皮AI闯关学习 / 闯关 / 学习者」，本地演示时一眼看出是课程仓库。本轮把两端术语对齐，并把仓库对外可见的上游痕迹收敛到「只剩致谢与 LICENSE」。

### 做了什么

- 小程序端：导航栏短名「内训考核」+ 约 32 条文案考核化（闯关→考核、学习者→同事、通关报告→考核复盘、经验值→考核积分、🐟→📋），`dist` 重新编译验证
- 后端：出题/复盘 prompt 的人设与场景描述改企业培训口径（字段名一个没动）、Swagger 标题、`users.nickname` 默认值 学习者→员工并**补幂等迁移回填存量行**
- 线上：重建镜像 + 重启容器，`mysql_initialized` 无报错，Swagger 标题已是新品牌，存量昵称已回填
- 仓库：README 从作者的推广文案重写为自研口吻（保留「来源与致谢」+ 改造清单），docs 12 处品牌名同步，克隆指引改指本项目仓库，2 个带旧名的原型文件 `git mv`
- 顺手排雷：`frontend/config/prod.ts` 的 `API_BASE_URL` 原指向作者演示服 `ai-learn.codefather.cn`

### 踩坑

| 坑 | 现象 | 真因 |
| --- | --- | --- |
| 全称放不进微信导航栏 | 「企业内部培训智能考核系统」12 字在小屏被截断 | 官方文档不写字数上限，但作者代码里已留证据：`pages/quiz/index.tsx:24` 把动态标题硬截 `.slice(0, 10)`。同一个约束要反过来用——短名放导航栏，全称放正文 |
| 改 prompt 改到线上 | 小程序端要改文案，结果网页端 AI 输出也变了 | `generate_report` 被 `report_service.py:23`（小程序）和 `assessment_service.py:168`（网页端）共用。**共享 LLM 链路上的文案不是某一端的私有资产** |
| 改默认值不生效 | 建表语句已改 `DEFAULT '员工'`，老库仍是 `学习者` | `CREATE TABLE IF NOT EXISTS` 对已存在的表是**空操作**，不会改列定义。必须在迁移函数里显式 `ALTER ... MODIFY` + `UPDATE` 回填 |
| 改文案把测试改红了 | `test_user_api.py:26,54` 断言默认昵称 | 文案进了断言就成了契约。改默认值必须同批改断言，否则绿基线破 |
| 以为 8080 能绕开备案 | `exam.3hao-ui.cn:8080` 返回 403 | 阿里云拦截**按域名备案状态判定，与端口无关**。实测对照：`.cn` 域名一律 403（`Server: Beaver` / `Non-compliance ICP Filing`），非 `.cn` 的 Host 与 IP 直连均 200 |
| 容器里查中文全是 `?` | `SELECT nickname` 显示 `?????` | 容器内 mysql 客户端默认字符集不是 utf8mb4，加 `--default-character-set=utf8mb4` 即可，不是数据坏了 |

### 下次注意

1. **改列默认值 = 改建表语句 + 写迁移 + 回填存量，三件事。** 只做第一件在开发库上永远"看起来生效"，因为开发库常常是新建的。
2. **改任何 LLM prompt 之前，先 `grep` 谁在调这条链。** 共用链路的改动天然是跨端改动，要按跨端改动的验收标准走（重建镜像 + 线上回归）。
3. **文案改名要连带扫测试断言与 mock 数据。** 本轮 4 个测试文件里的标题/昵称断言必须同步，否则要么红、要么假绿。
4. **归档文档不要为了口径统一去改写正文。** 早期设计文档写的是当时的判断，改写了就失去价值；正确做法是标题换品牌 + 顶部加一行「术语说明」指向当前定位。
5. **公开仓库的归属处理：删干净 ≠ 抹掉来源。** 保留 `LICENSE`、保留上游提交历史、README 写清"基于 X 二次开发 + 我独立做了什么"，比假装原创更经得起面试追问。
6. **验证线上镜像是否真的带上了新代码，`docker exec ent-backend grep` 比再花一次大模型调用便宜。** 静态字符串直接在镜像里查。
7. 小程序「关于小程序」面板里的名字由平台分配，测试号改不了；导航栏标题才是代码可控的那一个。
8. **厂商的拦截规则要实测，不要按"通常"推断。** 上轮我记了"非标端口通常放行"，这轮直接证伪。
