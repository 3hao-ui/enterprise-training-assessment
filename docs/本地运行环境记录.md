# 本地运行环境记录（Windows）

本文件记录 `保姆级本地运行指南.md` 在本机（Windows + Git Bash）落地后的**实际状态**，
以及与该指南不一致的地方。后续重启项目或排查问题时先看这份。

## 一、当前可用的启动方式

三个进程，MySQL 和后端必须常驻，前端按需。

```bash
# 1) MySQL（免安装 zip 版，不是 Windows 服务，每次开机要手动拉起）
cd /g/tools/mysql-8.0.29-winx64
./bin/mysqld.exe --defaults-file="G:\\tools\\mysql-8.0.29-winx64\\my.ini" --console

# 2) 后端（项目根目录下执行，端口 8000）
cd backend && ./venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 3) 前端 H5（另开终端，端口 10086）
cd frontend && npm run dev:h5
```

验证：`http://localhost:8000/api/v1/health` 返回 `{"status":"ok"}`；
`http://localhost:8000/docs` 可打开接口文档；H5 首页 `http://localhost:10086/`。

MySQL 连接信息：`root` / 密码见 `backend/.env` 的 `MYSQL_PASSWORD`（本机开发用），
库名 `yu_ai_learn`，7 张表由后端启动时 `MYSQL_AUTO_INIT=true` 自动创建。

## 二、与《保姆级本地运行指南》的差异

### 1. `DEEPSEEK_MODEL` 必须改成 `deepseek-flash`（指南写的是 `deepseek-chat`）

DeepSeek 官方已于 **2026-07-24 停用 `deepseek-chat` / `deepseek-reasoner`** 两个模型名，
V4.1-Flash 发布公告明确要求 `Set your model to deepseek-flash`。
沿用仓库默认值会导致出题调用直接失败。已在 `backend/.env` 中改正。

### 2. `.env` 里未申请的 Key 必须留空，不能保留占位符

`.env.example` 给的是 `your_tavily_api_key`、`your_dashscope_api_key`、`your_cos_secret_id` 这类
**非空字符串**，而代码用"有值即已配置"来判断（如 `cos_service.py:52` 检查四个 COS 字段的真值、
`rag_service.py:48` 检查 `enable_web_search and tavily_api_key`）。
保留占位符会让联网搜索、知识库、生图拿假 Key 去请求并报错，而不是干净地降级。
本机现状：Tavily / DashScope / COS / 微信 四项全部留空，只有 DeepSeek 配了真实 Key。

### 3. Taro 依赖预编译（prebundle）已关闭

npm 12 解析出的 `enhanced-resolve` / `webpack-virtual-modules` 与 Taro 4.1.11 的 prebundle 不兼容，
`npm run dev:h5` 启动即抛 `TypeError: options.roots.map is not a function` 和
`finalInputFileSystem._writeVirtualFile is not a function`。
已在 `frontend/config/index.ts` 把 `compiler` 由 `'webpack5'` 改为带 `prebundle.enable: false` 的对象。

### 4. 补了仓库缺失的 `frontend/src/index.html`

`@tarojs/webpack5-runner` 的 `H5WebpackPlugin` 只在 `src/index.html` 存在时才注册 HtmlWebpackPlugin。
仓库里没有这个文件（所以课程只提供 `dev:weapp`），导致 H5 构建只产出 js、不产出页面，
访问 dev server 看到的是 webpack 的目录索引页。
已按 Taro 规范补齐：挂载点必须是 `<div id="app">`（`@tarojs/plugin-framework-react` 里
`document.getElementById('app')`），并保留 `<%= htmlWebpackPlugin.options.script %>`
以维持 pxtransform 的 rem 适配。

### 5. 前端依赖需要 `--legacy-peer-deps`

`react-refresh@^0.18.0` 与 `babel-preset-taro@4.1.11` 要求的 `^0.14.0` 冲突，
npm 12 严格校验下 `npm install` 直接 ERESOLVE 失败。用
`npm install --legacy-peer-deps --registry=https://registry.npmmirror.com` 可正常安装。

### 6. 测试号申请入口：课程给的地址已失效

`docs/保姆级本地运行指南.md` 第 2.5 节写的 `https://developers.weixin.qq.com/sandbox` 已不可用：
扫码登录微信开放社区后会被跳转到 `community/develop/mixflow`（论坛首页），看不到 AppID。

官方文档《申请测试号》给出的有效地址是 **`https://mp.weixin.qq.com/wxamp/sandbox`**，
该页不需要社区登录，扫一次码就直接显示 AppID / AppSecret。

### 7. 仓库自带的 AppID 是作者的，必须替换

`frontend/project.config.json` 里提交的是 `wxe75e6433459ffc7a`（课程作者自己的小程序），
直接导入会用它，导致 `code2session` 换不到 openid。已改为本机测试号 AppID。

注意 `frontend/project.config.json` 与 `backend/.env` 的 `WECHAT_APP_ID` **必须是同一个**，
否则换取 openid 会失败。另外该文件里写的是 `"miniprogramRoot": "dist/"`，
所以导入 `frontend` 或 `frontend/dist` 都能打开；本项目按课程文档统一导入 `frontend/dist`。

## 三、已实测通过的范围

### H5 端（未登录）

出题 → 答题（即时判分、解析、经验值）→ 复盘报告（掌握度、薄弱点、知识总结、建议、题目回顾）
全链路跑通，单次出题约 7 秒。此模式下不写库（`quiz_sessions` 等计数为 0），符合项目"可选登录"设计。

### 微信小程序端（已登录）

- 微信开发者工具 Stable 2.02.2608070 导入 `frontend/dist`，模拟器正常渲染
- 「本地设置」勾选「不校验合法域名…」后，`http://localhost:8000` 可正常请求
- `POST /api/v1/user/login` 返回 200，`code2session` 用测试号成功换到 openid
- `/user/profile`、`/user/quizzes` 由 401 转为 200
- `users` 表落库成功（真实 openid、昵称"学习者"、`total_xp`、`created_at`）

登录态下完整跑一次闯关后的落库实测：

| 表 | 行数 | 说明 |
|---|---|---|
| `users` | 1 | `total_xp` = 12，与「我的」页经验值一致 |
| `quiz_sessions` | 2 | 每次生成题目即建一行，`questions_json` 存 5 题 |
| `answer_records` | 1 | 一次完整作答一行（**不是每题一行**），明细在 `records_json`，`total_questions`=5、`correct_count`=1、`accuracy`=20.00 |
| `reports` | 1 | 与完成作答的那次 `quiz_id` 对应 |

「我的」页显示"闯关次数 2 / 平均正确率 20%"且列表里有一条"0 题 · 正确率 0%"，是因为
`quiz_sessions` 在建题时就写入，而 `answer_records` 只在答完提交时写入——
中途放弃的那次只留下空 session，属正常行为，不是丢数据。

### 模拟器 Console 的两条报错（均无害）

- `GET /api/v1/user/quizzes 401`：冷启动时首页先于登录完成发出请求，登录后自动转 200
- `[渲染层错误] <button>: chooseAvatar:fail cancel`：头像选择器被取消，用户主动行为

## 四、已停用的功能（本项目主动裁剪，非缺陷）

### 联网出题（Tavily）— 已关闭

`backend/.env` 置 `ENABLE_WEB_SEARCH=false`。`search_service.py:119` 据此直接短路，
`rag_service.py:48` 也不再注册 Tavily 工具。后端日志会打 `web_search_disabled`。
零代码改动，出题回归通过（关闭后 `POST /quiz/generate` 仍 200，约 8 秒）。

### 题目生图 — 前端入口已移除

改动仅限前端首页：
- `frontend/src/pages/index/index.tsx`：删除「🖼️ 为题目生成配图」开关整块 UI、
  `generateImages` state、`image_notice` 的 toast 分支；调用改为 `generateQuizAsync(trimmed)`
- `frontend/src/pages/index/index.scss`：删除随之失效的 `.image-toggle-*` / `.toggle-pill` / `.toggle-knob`
- 加载文案由「AI 正在联网搜索并生成题目...」改为「AI 正在生成题目...」，与实际链路一致

**后端生图代码（`image_service.py`、`cos_service.py`、`quiz_service._maybe_generate_images`）
是有意保留的，不是漏删。** 因为 `generate_images` 默认 `false` 且已无调用方传 `true`，
该路径永不触发；删它要动出题主流程、收益为零。若将来要恢复生图，只需配好百炼生图 Key + 腾讯云 COS
并把首页开关加回来。

`frontend/src/services/api.ts` 里 `generateQuizAsync` 的 `generateImages = false` 形参同理保留为默认值。

### 知识库 RAG（阿里云百炼）— 已启用并实测通过

`backend/.env` 已填入 `DASHSCOPE_API_KEY`。该 Key 是 `sk-ws-` 开头的工作空间 Key，
**已实测确认具备 Embedding 权限**（走项目自身 `get_embeddings()` 返回 1024 维向量），
且继续使用旧域名 `https://dashscope.aliyuncs.com/compatible-mode/v1` 即可，无需换成
带 WorkspaceId 的 `*.maas.aliyuncs.com` 新域名。

Embedding 模型 `text-embedding-v4` 已对照阿里云百炼官方文档核实：仍在积极支持、未被替代。

端到端实测（Markdown 文档 → 出题）：

```
kb_document_processing_started → document_loaded_and_split(file_type=md, chunk_count=1)
→ document_chunks_added → kb_document_processing_completed
→ rag_agent_starting → rag_agent_completed(elapsed_ms=5875) → rag_context_fetched(length=1760)
```

`kb_documents` 表状态 `ready`；向量库落在本机 `backend/data/chroma`（`chroma.sqlite3` + collection 目录），
每用户一个 collection（`kb_user_{id}`）。基于该文档出题约 11 秒，生成内容的措辞与原文一致，
说明检索确实命中而非模型自由发挥。

> 日志里 `user_input='TCP xxxx'` 显示为乱码只是 Windows 控制台/终端的编码渲染问题，
> 实际入库和出题结果中的中文都正常，不是存储 bug。
