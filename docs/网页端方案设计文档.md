## 1. 总体架构

```
浏览器(面试演示)
   │  http://<你的服务器公网IP>:8080
   ▼
Nginx (宝塔管理)
   ├── /            → web/dist 静态文件 (Vite 构建产物)
   └── /api/*       → 反向代理 127.0.0.1:8000
                        ▼
                   FastAPI backend (Docker 容器)
                        ├── MySQL 8.0   (宝塔一键安装, 127.0.0.1:3306)
                        ├── ChromaDB    (容器内卷挂载持久化)
                        ├── DeepSeek    (出题/报告)
                        └── 百炼 Embedding (RAG)
```

小程序端（本地演示）继续直连本地 backend，**代码与接口零改动**。

## 3. 数据库变更（开闭：只加列加表，不改既有语义）

### 3.1 `users` 表加列 + 放宽 openid

```sql
ALTER TABLE users
  MODIFY openid VARCHAR(64) NULL,                    -- 网页账号无 openid；MySQL 唯一索引允许多个 NULL
  ADD COLUMN username      VARCHAR(64)  NULL,
  ADD COLUMN password_hash VARCHAR(100) NULL,
  ADD COLUMN role          VARCHAR(16)  NOT NULL DEFAULT 'employee',  -- admin | employee
  ADD COLUMN department    VARCHAR(64)  NOT NULL DEFAULT '',
  ADD COLUMN status        TINYINT      NOT NULL DEFAULT 1,           -- 1 启用 0 停用
  ADD UNIQUE KEY uk_users_username (username);
```

- 微信登录链路（`user_service.handle_login`）**一行不改**：它仍按 openid 查/建用户并写 openid。
- 网页账号 `openid = NULL`，靠 `username` 唯一标识。
- 现有 7 张表、既有数据全部保留。

### 3.2 新增表 `assessments`（考核任务）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK AI | |
| assessment_id | VARCHAR(64) UNIQUE | 业务 ID |
| title | VARCHAR(255) | 考核名称 |
| doc_id | VARCHAR(64) | 绑定的知识库资料（出题来源） |
| question_count | INT | 题量 3–10 |
| difficulty | VARCHAR(10) | easy/medium/hard/mixed |
| pass_accuracy | DECIMAL(5,2) | 及格正确率，默认 60 |
| deadline | DATETIME NULL | 截止时间，NULL 表示不限 |
| status | ENUM('open','closed') | 管理员可关闭 |
| created_by | BIGINT | 管理员 user_id |
| created_at / updated_at | DATETIME | |

### 3.3 新增表 `assessment_records`（考核成绩）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK AI | |
| assessment_id | VARCHAR(64) | FK→assessments |
| user_id | BIGINT | FK→users |
| quiz_id | VARCHAR(64) | 关联本次答题（复用 quiz_sessions/reports） |
| accuracy | DECIMAL(5,2) | 正确率 |
| passed | TINYINT | 是否达到 pass_accuracy |
| duration_seconds | INT | 用时 |
| created_at | DATETIME | |

允许重考：同一 (assessment_id, user_id) 可多条，报表展示每次记录并标注最佳成绩。

## 4. 后端接口设计（新增路由文件，不改既有路由）

JWT payload **只加字段**：`{user_id, openid, exp, role}`。
- `get_current_user` 不读 role → 小程序旧 token、旧调用完全不受影响。
- 新增 `get_current_admin`：解析 role，非 admin 抛 403。
- `create_token` 增加可选参数 `role: str = ""`，默认值保证既有调用签名不变。

### 4.1 `routes/auth.py`（新增）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/auth/login` | `{username, password}` → `{token, user}`；校验 status=1 |

### 4.2 `routes/admin.py`（新增，全部过 `get_current_admin`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/admin/employees` | 列表（分页+搜索）/ 新建（username, password, nickname, department） |
| PUT | `/admin/employees/{user_id}` | 改昵称/部门/启用停用 |
| POST | `/admin/employees/{user_id}/reset-password` | 重置密码 |
| GET/POST | `/admin/assessments` | 列表 / 发布 |
| PUT | `/admin/assessments/{assessment_id}` | 关闭/改截止时间 |
| GET | `/admin/assessments/{assessment_id}/records` | 该考核全部员工成绩 |
| GET | `/admin/records` | 全员成绩（可按 user_id 过滤） |

资料管理**不新建接口**：直接复用既有 `/knowledge/documents`（已按 user_id 隔离，管理员即其上传者）。

### 4.3 `routes/assessment.py`（新增，员工侧）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/assessments/mine` | 我的考核（pending/done/expired 分组） |
| POST | `/assessments/{assessment_id}/start` | 校验未过期+未关闭 → 复用 quiz 生成（doc_id 固定）→ 返回 quiz_id + 题目 |
| POST | `/assessments/{assessment_id}/submit` | 复用判分+报告 → 写 assessment_records → 返回报告 |

> 出题/判分/报告全部调用既有 `quiz_service` / `scoring_service` / `report_service`，不复制逻辑。

## 5. 网页前端设计（新目录 `web/`，与 `frontend/` 完全独立）

```
web/
├── src/
│   ├── api/          # axios 封装，契约同 {code,message,data}
│   ├── pages/
│   │   ├── login/            # 统一登录页
│   │   ├── admin/            # 员工管理 / 资料管理 / 考核管理 / 成绩报表
│   │   └── employee/         # 我的考核 / 答题 / 报告 / 我的成绩
│   ├── router/       # 路由守卫：无 token → /login；role 不匹配 → 403 页
│   └── components/
└── vite.config.ts    # dev 代理 /api → localhost:8000
```

- 答题页交互（逐题即时判分+讲解）从 `frontend/src/pages/quiz/index.tsx` 移植逻辑、用 antd 重写 UI。
- 管理端四页全部用 antd `Table`/`Form`/`Upload`/`Statistic`，不写自定义样式。

## 6. 部署方案（2026-09-20 按服务器实测截图修订）

- **服务器**：阿里云 ECS 2c4G/40G，华南2，公网 IP `<你的服务器公网IP>`，按量付费；
  宝塔 v13.0.0 / Ubuntu 22 / Nginx 1.24.0 / 进程守护管理器 3.0.6 已装。
  **与现有项目 miaocun 共用本机，不新开服务器**。
  实测依据：内存仅 580MB/3.5GB（16%）、负载 0%、磁盘 5.5/39GB；
  本套预估占用 1.2~1.5GB，余量约 2.9GB，富余一倍以上。
- **端口**：现有项目占 18080；本套 Nginx 监听 **8080**，互不冲突。
- **组件分工**：
  - Nginx（宝塔已装）：新增站点托管 `web/dist`；`location /api/` 反代 `127.0.0.1:8000`。
  - MySQL 8.0：**宝塔当前未安装（数据库数=0）**，软件商店一键安装，仅监听 127.0.0.1，
    新建 database `ent_training`。
  - backend：**Docker 容器运行**（仓库现有 `backend/Dockerfile`），`backend/data` 挂载宿主机卷持久化 Chroma。
    用户拍板保留 Docker（2026-09-20）：作为学习点与简历亮点，优先于"少装一套运行时"的简化考量。
    前置动作：服务器当前未装 Docker，S9 部署时先安装（宝塔「Docker」菜单或 `apt install docker.io`）。
    进程守护管理器 3.0.6 已装，作为 Docker 方案失败时的回退运行方式。
- **HTTPS 升级（取代原"HTTP 明文"方案，零成本）**：
  用户已有域名 `3hao-ui.cn` 且成功申请过 Let's Encrypt 免费证书（DNS 验证）。
  1. 域名解析加 A 记录：`exam.3hao-ui.cn → <你的服务器公网IP>`
  2. 宝塔「SSL → 免费证书」为 `exam.3hao-ui.cn` 申请证书（DNS 验证）
  3. Nginx 8080 站点配 SSL → 访问地址 `https://exam.3hao-ui.cn:8080`
  依据：未备案拦截针对 80/443 端口，非标端口 + 域名通常放行；S9 部署时实测验证。
  **Fallback**：若子域名实测被拦，退回 `http://<你的服务器公网IP>:8080`（该风险用户已书面接受）。
  注：现有站点浏览器报"不安全"是因为签给 `3hao-ui.cn` 的证书部署在以 IP 命名的站点上，
  主机名不匹配所致，非证书损坏。
- **密钥**：服务器 `/www/wwwroot/ent-training/backend/.env`，`chmod 600`，不入库。
- **网页终端不可用**：宝塔 v13 网页终端 websocket 空白页；
  改用阿里云控制台「实例 → 远程连接 → Workbench 远程连接」或本地 `ssh root@<你的服务器公网IP>`。
- **部署后安全加固（顺手项）**：宝塔面板仍用默认端口 8888 且提示安全风险 19 条，
  上线验证通过后改面板端口并处理高危项。

## 7. 被否方案与理由（留档）

| 被否方案 | 否决理由 |
| --- | --- |
| 复用 Taro `build:h5` 当网页端 | 手机窄屏 UI、无账号登录，不像企业系统；只配当部署链路验证品 |
| Vue3 + Element Plus | 与现有 React 代码不同源，等于重学一套框架，求职时间线不划算 |
| 手机号/邮箱验证码登录 | 短信要买包+签名审核；邮箱 SMTP 延迟打断演示；都不像企业内部系统 |
| 独立 `employees` 表 | 成绩/历史/资料都要双写或 union，复杂度高于 users 加列 |
| `passlib` 做密码哈希 | 停维护（1.7.4, 2020），与 bcrypt>=4.1 冲突报 `__about__` 错误 |
| 微信云托管默认域名 | 官方明说"默认公网域名仅可做测试之用，线上生产需绑定已备案自定义域名" |
| 境外免费平台（Vercel/Render） | 演示环境在中国大陆，延迟高+冷启动，面试现场有翻车风险 |
| 现在就走域名+备案 | 按量付费不能备案；转包年包月+备案需 7~20 天，卡演示时间线 → 列为第二阶段 |
| antd 5 | 6.6.4 已是 latest 且发布满 10 个月；官方文档即最新版，无回退必要 |
