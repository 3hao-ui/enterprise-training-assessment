## 0. 架构与端口规划

```
浏览器 ──HTTPS:8080──> Nginx(宝塔)
                          ├── /            → /www/wwwroot/ent-training/web/dist（静态）
                          └── /api/        → 127.0.0.1:8010（Docker 后端，容器内 8000）
                                                └── MySQL（Docker，仅内网 3306）
```

| 端口 | 用途 | 是否对公网开放 |
| --- | --- | --- |
| 8080 | 前端 + 反代入口 | 是 |
| 8010 | 后端 uvicorn（宿主机映射；容器内仍 8000） | **否**，只绑 127.0.0.1，由 Nginx 反代 |
| 3306 | MySQL | 否，只在 Docker 内网 |
| 8888 | 宝塔面板 | 仅限你的 IP |

> **为什么不用 8000**：2026-09-20 实测 `ss -tlnp` 显示 `127.0.0.1:8000` 已被现有 miaocun 项目的
> python 进程（pid 21676）占用，本项目改用宿主机端口 **8010**。
> 结论：安全组不需要为后端开任何端口；8080 保留即可。

## 2. 安装 Docker（用阿里云源，不要用 get.docker.com）

`get.docker.com` 在国内会被连接重置，这是已知问题。改用阿里云 apt 源：

```bash
# 2.1 前置包
apt-get install -y ca-certificates curl gnupg

# 2.2 添加 Docker 官方 GPG 密钥（走阿里云镜像）
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg \
  | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg

# 2.3 写入软件源
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  > /etc/apt/sources.list.d/docker.list

# 2.4 安装
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 2.5 启动并设开机自启
systemctl enable --now docker

# 2.6 验证（两条都要有版本号）
docker --version
docker compose version
```

## 5. 服务器环境变量（不进镜像）

在 `/www/wwwroot/ent-training/` 下创建 `.env`，键值与你本地 `backend/.env` 一致：

```bash
cd /www/wwwroot/ent-training
cat > .env <<'EOF'
DEEPSEEK_API_KEY=（从本地 backend/.env 复制）
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
ENABLE_WEB_SEARCH=false
DASHSCOPE_API_KEY=（从本地 backend/.env 复制）
DASHSCOPE_EMBEDDING_MODEL=text-embedding-v4
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
MYSQL_HOST=mysql
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=（自己设一个强密码，这就是 MySQL root 密码，记住）
MYSQL_DATABASE=ent_training
MYSQL_AUTO_INIT=true
JWT_SECRET=（自己随机生成一串，别用默认值）
JWT_EXPIRE_MINUTES=43200
ADMIN_USERNAME=admin
ADMIN_PASSWORD=（管理员登录密码，自己定）
TZ=Asia/Shanghai
EOF
chmod 600 .env
```

> 注意 `MYSQL_HOST=mysql` —— 这是 Docker 服务名，不是 127.0.0.1。
>
> ⚠️ **`.env` 只有一个，且不在 `backend/` 下。**
> compose 里 backend 服务写的 `env_file: .env` 是**相对 `docker-compose.yml` 所在目录**解析的，
> 生效文件就是 `/www/wwwroot/ent-training/.env`。容器内不存在 `/app/.env`
> （镜像构建时被 `.dockerignore` 排除了），所以 `docker exec ent-backend cat /app/.env`
> 必然报 `No such file or directory`，这不代表没配置。查真实生效值要用
> `docker exec ent-backend env | grep MYSQL`。
>
> 排查连接类问题时的对照命令：
> `docker inspect ent-mysql --format='{{range .Config.Env}}{{println .}}{{end}}' | grep MYSQL_ROOT_PASSWORD`
> —— 它能告诉你 MySQL 容器**实际**被创建时用的密码，与 `.env` 对不上就是改过 `.env` 但没重建卷。

## 6. Docker Compose 定义

```bash
cd /www/wwwroot/ent-training
cat > docker-compose.yml <<'EOF'
services:
  mysql:
    image: mysql:8.0
    container_name: ent-mysql
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DATABASE}
      TZ: ${TZ}
    command: >
      --character-set-server=utf8mb4
      --collation-server=utf8mb4_unicode_ci
      --default-time-zone=+08:00
    volumes:
      - ent_mysql_data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-p${MYSQL_PASSWORD}"]
      interval: 10s
      timeout: 5s
      retries: 10

  backend:
    build:
      context: ./backend
    container_name: ent-backend
    restart: always
    env_file: .env
    environment:
      PORT: "8000"
    volumes:
      - ./data/chroma:/app/data/chroma
    ports:
      - "127.0.0.1:8010:8000"
    depends_on:
      mysql:
        condition: service_healthy

volumes:
  ent_mysql_data:
EOF
```


> 在宝塔「文件」里直接框选 `dist` 下的文件上传，只会传上根级的 `index.html`、`favicon.svg`、`icons.svg`
> 三个文件，**`assets/` 子目录不会被带上**。`index.html` 引用的 `assets/index-<hash>.js` 找不到就 404，
> 表现为整页白屏（浏览器控制台报 `Failed to load module script` / 404）。

打包（Windows 原生支持 zip，宝塔可直接解压，比 tar 省事）：

```bash
# 本机 Git Bash
cd "G:/ai-code/Enterprise-Internal-Training-Intelligent-Assessment/web"
powershell -NoProfile -Command "Compress-Archive -Path 'dist\*' -DestinationPath 'ent-web-dist.zip' -Force"
```

宝塔「**文件**」→ 进入 `/www/wwwroot/ent-training/web/`（注意是 `web`，不是 `dist`）→
「**上传**」`ent-web-dist.zip` → 右键「**解压**」→ 解压到填 `/www/wwwroot/ent-training/web/dist`（同名文件会覆盖）。

解压后进 `dist/assets/` 核对：JS 文件名里的 hash 必须与 `index.html` 中引用的**完全一致**。

改完前端代码重新发布时，产物 hash 会变，浏览器可能仍缓存旧 `index.html`，验收前务必 **Ctrl+F5** 强刷。

## 8. 宝塔建站 + Nginx 反代

1. 宝塔左侧「**网站**」→「PHP项目」标签右侧的「**添加站点**」按钮
   - **域名**：`exam.3hao-ui.cn`
   - **PHP 版本**：选「**纯静态**」
   - **根目录**：`/www/wwwroot/ent-training/web/dist`
   - 数据库：不创建

> ⚠️ **宝塔「域名」输入框的三条硬限制**（今天全部踩过）：
>
> | 填法 | 报错 |
> | --- | --- |
> | `<你的服务器公网IP>:8080` | 端口范围不合法 |
> | `4712034207`（纯数字） | 当前域名格式错误 |
> | `<你的服务器公网IP>`（已有站点占用该 IP） | 您添加的域名已存在 |
>
> 一台服务器上跑多个项目时，IP 早被第一个站点占了。**解决办法**：建站点时填一个只用于标识的
> 占位子域名（如 `ent.4712034207.local`，必须含字母和点才通过校验），根目录照样指向本项目，
> 建站成功后再去配置文件里把真实访问域名与 IP 补进 `server_name`。宝塔的域名框只是站点标识，
> Nginx 实际按 `listen` 端口 + `server_name` 匹配。

2. 建好后点该站点行的「**设置**」→「**配置文件**」标签，改三处：
   - `listen 80;` → `listen 8080;`
   - `server_name` 补齐真实访问入口：`server_name ent.4712034207.local exam.3hao-ui.cn <你的服务器公网IP>;`
   - 在 `server{}` **内部**、闭合花括号**之前**加入下面两个 location：

```nginx
    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8010;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 180s;
    }
```

3. 点「**保存**」→ 宝塔左侧「**软件商店**」→ Nginx 行「**重载**」（不是重启，避免中断）

> ⚠️ **手改配置的花括号陷阱**：宝塔自动生成的配置里，`error_log /www/wwwlogs/xxx.error.log;`
> 后面紧跟着一个**闭合 `server{}` 的右花括号**。如果把上面的 `location` 块直接粘在这行之后，
> 它们就落到了 `server` 块外面，保存时报：
> `nginx: [emerg] "location" directive is not allowed here in /www/server/panel/vhost/nginx/xxx.conf:67`
> 正确做法：把 `location` 插在**那个右花括号之前**；确认整个文件最终只有一个 `server{}` 且被正确闭合。
> 宝塔保存前会自动跑 `nginx -t`，报错就保存不了，按报错行号定位即可。

此时访问 `http://exam.3hao-ui.cn:8080`（或 `http://<你的服务器公网IP>:8080`）应能看到登录页。
再访问 `http://<你的服务器公网IP>:8080/api/v1/health` 应返回 `{"code":0,...}`，这条通了才说明
Nginx → 127.0.0.1:8010 → 容器 的反代链路完整。

## 9. 子域名 HTTPS（免费证书，无需备案）

> ⛔ **本节标题的"无需备案"结论已被 2026-09-20 实测推翻，在完成 ICP 备案之前整节不可执行。**
>
> 用 `curl --resolve` 把任意 Host 强制解析到服务器 IP 后逐一对照（均打 8080）：
>
> | Host 头 | 结果 |
> | --- | --- |
> | `<公网IP>`（IP 直连） | 200，`/api/v1/health` 正常 |
> | `exam.3hao-ui.cn` | **403**，`Server: Beaver`，页面标题 `Non-compliance ICP Filing`，跳转 `www.aliyun.com/beian/beian-block` |
> | `3hao-ui.cn` | **403**，同上 |
> | `3hao-ui.com` / `3hao-ui.net` / `baidu.com` | 200 |
>
> 结论两条：① 阿里云的未备案拦截**按域名判定，与端口无关**，换端口绕不过去；
> ② `.cn` 走 CNNIC 注册局所以被强制拦截，非 `.cn` 域名当前不拦（灰色地带，厂商随时可收紧，不宜作长期方案）。
> 另注意 `exam.3hao-ui.cn` **连 A 记录都还没建**（`nslookup` 返回 Non-existent domain），
> 所以本节 9.1 那步是前置缺失，不是配置错。
>
> **当前可用地址：`http://<你的服务器公网IP>:8080`。** 要上域名就得先备案（个人备案 7~20 天，
> 且按量付费实例需先转包年包月才拿得到备案服务码）。以下原步骤保留备查，备案下来后可直接照做。

### 9.1 DNS 解析

阿里云控制台 →「**域名与网站**」→ `3hao-ui.cn`「**解析**」→「**添加记录**」：

| 记录类型 | 主机记录 | 记录值 | TTL |
| --- | --- | --- | --- |
| A | `exam` | `<你的服务器公网IP>` | 10 分钟 |

### 9.2 申请证书

宝塔左侧「**SSL**」→「**Let's Encrypt**」标签 → 勾选 `exam.3hao-ui.cn` →
验证方式选「**DNS 验证**」→ 申请。

> 用 DNS 验证而非 HTTP 验证：因为 80 端口未开放且域名未备案，HTTP 验证会失败。

### 9.3 站点启用 SSL

站点「**设置**」→「**SSL**」→ 打开「**强制 HTTPS**」→ 保存。
配置文件里确认 `listen 8080 ssl;` 且证书路径正确。

最终地址：**`https://exam.3hao-ui.cn:8080`**

> 若第 11 步实测发现未备案域名被拦，直接改用 `http://<你的服务器公网IP>:8080`，
> 只需把站点域名改成 IP、删掉 SSL 段即可，功能不受影响。

## 10. 初始化管理员账号 + 上线验收清单

MySQL 卷是空的，`users` 表建好但没有任何账号，必须先建管理员才能登录。

```bash
cd /www/wwwroot/ent-training
docker exec ent-backend python -m scripts.init_admin admin '你定的管理员密码'
```

镜像里没有该脚本时（老镜像），用这条免重建的兜底命令，直接在运行中的容器里建：

```bash
docker exec ent-backend python -c "
import asyncio, sys
sys.path.insert(0, '/app')
import aiomysql
from app.core.config import get_settings
from app.core.password import hash_password

async def main():
    s = get_settings()
    conn = await aiomysql.connect(host=s.mysql_host, port=s.mysql_port, user=s.mysql_user,
                                  password=s.mysql_password, db=s.mysql_database,
                                  charset=s.mysql_charset, autocommit=True)
    async with conn.cursor() as cur:
        await cur.execute(
            'INSERT INTO users (username, password_hash, role, department, status) '
            'VALUES (%s, %s, %s, %s, 1)',
            ('admin', hash_password('你定的管理员密码'), 'admin', '系统管理'))
        await cur.execute('SELECT id, username, role, status FROM users WHERE username=%s', ('admin',))
        print('created:', await cur.fetchone())
    conn.close()

asyncio.run(main())
"
```

> ⚠️ 两条极易踩的事实：
> 1. **密码哈希在 `app/core/password.py`**（直接用 `bcrypt`）。`app/core/security.py` 只做敏感词过滤，
>    从它 `import get_password_hash` 必然 `ImportError`。本项目没有用 passlib，别按网上常见写法来。
> 2. **`users.status` 必须是整数 `1`**。填 `'active'` 之类的字符串会被判为停用，
>    登录时报「账号已停用」。同理 `password_hash` 为空也会被统一报成「用户名或密码错误」。

登录返回 401 但哈希看起来正常时，先确认哈希是谁生成的：`$2b$12$` 开头、长度 60 是本项目 `hash_password`
的正常产物；若长度不对或前缀是 `$2a$`/`$2y$`，说明是别的库（passlib 等）生成的，两边对不上，直接重建账号最快。

## 11. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Connection reset` 拉取 docker 安装脚本 | 官方源被干扰 | 用第 2 节阿里云源 |
| `docker compose up` 卡在拉镜像 | 未配加速器 | 做第 2.7 步 |
| backend 反复重启 | 连不上 MySQL | 确认 `.env` 里 `MYSQL_HOST=mysql`，且 mysql 健康检查通过 |

### 11.1 面板/网站打不开：更新安全组 IP 白名单（三步）

**这是最高频的"故障"，而且不是故障。** 家庭宽带的公网 IPv4 是动态的，重新拨号、重启光猫、
换到手机流量都会变。IP 一变，安全组里那条 `/32` 白名单就把你挡在外面——表现是**浏览器一直转圈然后超时**，
而不是报错，所以很容易误以为服务挂了。

判断依据：如果 `http://<服务器IP>:8080` 别人能打开、你打不开，或者昨天还能进面板今天不行，
就是这个问题，**不需要动服务器上的任何东西**。

**第 1 步：查你当前的公网 IP**

在你自己的电脑浏览器打开 `https://ip.cn`（或 `https://www.ip138.com`），记下显示的 IP。

> ⚠️ 必须是 **IPv4**。手机流量下有些网络只给 IPv6，查到的地址填进安全组永远不会生效。
> 命令行查也行，注意加 `-4` 强制走 IPv4：
> `curl -4 -s https://api.ipify.org`

**第 2 步：改安全组授权对象**

阿里云 →「云服务器 ECS」→ 实例 →「安全组」→「入方向」→ 找到那条限制了你 IP 的规则
（端口 8888 / 以及你为面板、SSH 建的其它单 IP 规则）→「修改」→
把**授权对象**里的旧 IP 换成第 1 步查到的新 IP，保留 `/32` 后缀。

多条规则都绑了同一个旧 IP 时，逐条改，漏一条就还是打不开。

**第 3 步：验证**

刷新面板地址即可。仍不通就在本机 `Test-NetConnection <服务器IP> -Port 8888`（PowerShell）
看 `TcpTestSucceeded`，`False` 说明安全组还没放行到位。

> **演示现场救急**：如果正在面试/演示、来不及查 IP，可临时把授权对象改成 `0.0.0.0/0`
> （全网可访问）先进去，**演示完立刻改回单 IP**。面板 8888 端口暴露在公网时间越长越危险，
> 别把"临时"忘了。更稳妥的做法是提前把演示用的 8080 端口保持 `0.0.0.0/0`（本来就是公开网站），
> 只给面板和 SSH 留白名单——这样你 IP 变了只影响自己管理，不影响演示。

常用运维命令：

```bash
cd /www/wwwroot/ent-training
docker compose ps                 # 状态
docker compose logs -f backend    # 后端日志
docker compose restart backend    # 只重启后端
docker compose down               # 停止（数据在卷里，不会丢）
```
